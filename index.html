1-bob: Frontend Dasturchi Dunyosi va Web Qanday Ishlaydi?

Brauzer qanday ishlaydi?

Ko'pchilik o'rganuvchilar frontendni shunchaki chiroyli tugmalar va ranglar deb o'ylashadi. Biroq Senior Frontend muhandis bo'lish uchun brauzer qanday qilib siz yozgan bir necha qator kodni monitor ekranida harakatlanuvchi piksellarga aylantirishini (Pixel Pipeline) ich-ichidan tushunishingiz shart.

Zamonaviy brauzerlar (Google Chrome, Safari, Firefox) bir nechta parallel jarayonlardan (Multi-Process Architecture) iborat:

  • Browser Process — Brauzer oynasining boshqaruv paneli (URL satri, tabs, orqaga/oldinga tugmalari) va tarmoq/fayl resurslariga kirishni boshqaradi.
  • Renderer Process — Tab ichidagi veb sahifaning HTML, CSS, JavaScript kodlarini o'qiydi va uni ekranda chizadi. Xavfsizlik maqsadida har bir tab o'zining alohida Sandbox qilingan Renderer jarayonida ishlaydi.
  • GPU Process — Murakkab 3D va 2D grafik hisob-kitoblarni, CSS transform va animatsiyalarni asosiy protsessor (CPU) dan ajratilgan holda o'ta tezkor chizib beradi.

Critical Rendering Path (CRP)

Foydalanuvchi URL manzilini kiritgan soniyadan boshlab to ekranda birinchi piksel paydo bo'lguncha kechadigan zanjir Critical Rendering Path deyiladi:

URL Kiritildi -> DNS Lookup -> TCP Handshake -> TLS Handshake -> HTTP Request | +----------------------------------------------------------------------+ | v HTML Baytlari -> Belgilar (Characters) -> Tokenlar -> Tugunlar (Nodes) -> DOM Daraxti CSS Baytlari -> Belgilar (Characters) -> Tokenlar -> Tugunlar (Nodes) -> CSSOM Daraxti | DOM + CSSOM = RENDER TREE (Faqat ko'rinadigan elementlar) <------------+ | v LAYOUT (Reflow): Har bir elementning ekrandagi aniq koordinata va o'lchamini hisoblash | v PAINT (Repaint): Ranglar, chegaralar, matnlar va rasmlarni qatlamlarga (Layers) chizish | v COMPOSITE: GPU qatlamlarni birlashtiradi va ekranga yakuniy freymni chiqaradi (60-120 FPS)
💡 Pro Maslahat: display: none vs visibility: hidden

display: none berilgan element DOM daraxtida bo'ladi, lekin Render Tree ga kirmaydi! Shu sababli u ekranda hech qanday joy egallamaydi va layout hisob-kitobida qatnashmaydi. visibility: hidden esa Render Tree da bo'ladi, joy egallaydi, faqat bo'yalmaydi (Paint bo'lmaydi).

Tarmoq: DNS, TCP, TLS va HTTP/3

Brauzer serverdan ma'lumot olishi uchun quyidagi bosqichlarni bosib o'tadi:

  1. DNS qidiruvi (Domain Name System): Inson tushunadigan astra-academy.uz manzilini kompyuterlar tushunadigan IP manzilga (masalan, 104.21.45.12) aylantirish. Brauzer avval o'z keshidan, keyin OS keshidan va nihoyat ISP DNS resolveridan so'raydi.
  2. TCP 3-Way Handshake: Ishonchli aloqa kanali o'rnatiladi (SYN -> SYN-ACK -> ACK).
  3. TLS Handshake (HTTPS): Sayt xavfsizligini ta'minlash uchun assimetrik shifrlash kalitlari almashinadi.
  4. HTTP/2 va HTTP/3 inqilobi: Qadimgi HTTP/1.1 da bitta ulanishda faqat bitta fayl ketma-ket yuklanar edi (Head-of-line blocking). Zamonaviy HTTP/2 multiplekslash (bitta ulanishda 100 lab faylni bir vaqtda parallel yuklash) imkonini berdi. HTTP/3 esa TCP o'rniga UDP asosidagi QUIC protokoliga o'tib, tarmoq almashganda (Wi-Fi dan 4G ga o'tganda) ulanish uzilmasligini ta'minladi.

DOM va CSSOM qurilishi

HTML parser baytma-bayt oqimni (stream) o'qiydi. Agar u tashqi skriptga duch kelsa (<script src="...">), u darhol HTML tahlilini to'xtatadi (Parse-blocking). Chunki JavaScript DOM ni o'zgartirishi mumkin!

Buning oldini olish uchun zamonaviy frontendda skriptlarga defer yoki async atributlari beriladi:

Atribut Yuklanish (Download) Bajarilish (Execution) Tartib (Order) Qachon ishlatiladi?
Oddiy <script> HTML ni to'xtatadi (Bloklaydi) Darhol bajariladi Uchrash tartibida Kritik bo'lmagan hollarda tavsiya etilmaydi
<script async> HTML bilan parallel yuklanadi Yuklanishi bilanoq HTML ni to'xtatib bajariladi Kim birinchi kelsa shu (Kafolatsiz) Mustaqil tahlil skriptlari (Google Analytics)
<script defer> HTML bilan parallel yuklanadi HTML to'liq o'qib bo'lingach (DOMReady) bajariladi HTML dagi aniq tartibda Asosiy frontend JavaScript kodlari (Tavsiya!)

Reflow vs Repaint farqi

Frontend animatsiyalarining sekinlashishi va telefon qotib qolishining 90% sababi — keraksiz Reflow chaqirishdir:

  • Reflow (Layout): Sahifadagi elementlarning kengligi (width), balandligi (height), chetlari (margin), joylashuvi (top, left) o'zgarganda sodir bo'ladi. Butun sahifaning geometriyasi qayta hisoblanadi. Bu protsessor uchun juda qimmat operatsiya!
  • Repaint: Elementning geometriyasi o'zgarmasdan, faqat tashqi ko'rinishi (color, background-color, box-shadow) o'zgarganda sodir bo'ladi.
  • Composite Only (Super Fast!): Faqatgina transform va opacity xossalari o'zgarganda, brauzer na Reflow, na Repaint qiladi! Barcha ish GPU xotirasida freymlar o'rtasida suriladi. Bu 60 va 120 FPS silliq animatsiyalarning poydevoridir!

Semantik HTML teglari shunchaki kodni chiroyli ko'rsatmaydi — ular 3 ta o'ta muhim vazifani bajaradi:

Accessibility (a11y) va ARIA rollari

A11y — Accessibility so'zining qisqartmasi bo'lib ("A" va "y" harflari orasida 11 ta harf bor). G'arb bozorida (AQSH va Yevropa Ittifoqida) a11y standartlariga (WCAG 2.1 AA) javob bermaydigan saytlar uchun qonuniy jarimalar mavjud (ADA compliance).

ARIA (Accessible Rich Internet Applications) atributlarining 1-oltin qoidasi: "Agar HTML da tabiiy semantik teg mavjud bo'lsa, hech qachon ARIA ishlatmang!". Masalan, <div role="button"> o'rniga oddiy <button> ishlatish kerak. Chunki haqiqiy tugma o'z-o'zidan Enter va Space tugmalarini tinglaydi va Tab bilan fokuslanadi.

3-bob: Professional CSS3, Flexbox va Grid Chuqur Tahlil

Box Model va box-sizing: border-box

CSS ning poydevori — Box Model. Har bir element 4 ta to'rtburchakdan iborat: Content, Padding, Border va Margin.

+----------------------------------------------------+ | MARGIN (Elementlar orasidagi tashqi bo'shliq) | | +--------------------------------------------+ | | | BORDER (Elementning chegarasi) | | | | +------------------------------------+ | | | | | PADDING (Chegara va matn oralig'i) | | | | | | +----------------------------+ | | | | | | | CONTENT (Matn yoki rasm) | | | | | | | +----------------------------+ | | | | | +------------------------------------+ | | | +--------------------------------------------+ | +----------------------------------------------------+

Standart CSS da (content-box): Agar elementga width: 200px bersangiz va unga padding: 20px qo'shsangiz, uning ekrandagi haqiqiy kengligi 240px bo'lib ketadi va layout buziladi! Shu sababli har bir zamonaviy loyiha quyidagi reset bilan boshlanadi: 

*, *::before, *::after {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

Stacking Context va z-index siri

Ko'p dasturchilar z-index: 9999999 yozsa ham element orqada qolib ketishidan shikoyat qilishadi. Sababi: Stacking Context (Taxlam Konteksti) tushunchasini bilmaslikdir.

Element quyidagi hollarda yangi Stacking Context yaratadi:

  • position: relative/absolute va z-index auto emas;
  • position: fixed yoki sticky;
  • opacity 1 dan kichik bo'lsa;
  • transform, filter, yoki perspective berilgan bo'lsa.

Agar ona element o'zining alohida stacking kontekstida pastroq qavatda bo'lsa, uning ichidagi bolaning z-index qiymati milliard bo'lsa ham, u tashqi ona elementdan yuqoriga chiqa olmaydi!

Flexbox: 1D Layout Mastery

Flexbox — bir o'lchamli (faqat qator YOKI faqat ustun) joylashtirish tizimi.

  align-items: center;            /* Ko'ndalang o'q (Cross Axis) bo'yicha markazlashtirish */
  gap: 1.5rem;                    /* Elementlar orasidagi zamonaviy bo'shliq */
}

.nav-search {
  flex: 1; /* Bo'sh qolgan barcha joyni egallash (grow: 1, shrink: 1, basis: 0) */
}

60 FPS animatsiyalar va GPU acceleration

Brauzer monitoriga har bir soniyada 60 ta kadr chizilishi kerak. Bu degani, brauzerda bitta kadrni hisoblab ekranga chiqarish uchun atigi 16.6 millisoniya (ms) vaqt bor!

Agar animatsiyada left yoki margin-top ishlatilsa, har bir 16 ms da CPU Reflow hisoblaydi va natijada kadrlar tushib qoladi (jank/stutter). To'g'ri yo'l: 

/* NOTO'G'RI (Lag qiladi) */
.box:hover {
  left: 200px;
}

/* ASTRA STANDARTI (60/120 FPS moydek silliq) */
.box {
  will-change: transform; /* Brauzerga buni alohida GPU qatlamiga olishni buyuradi */
  transition: transform 0.3s cubic-bezier(0.34, 1.56, 0.64, 1);
}
.box:hover {
  transform: translateX(200px);
}

5-bob: JavaScript Core: Dvigatel Ichiga Sayohat

V8 dvigateli va JIT kompilyatsiya

Google Chrome va Node.js da ishlaydigan V8 dvigateli JavaScript kodini qanday ijro etadi?

  1. Parser: Kodni o'qiydi va uni AST (Abstract Syntax Tree) ga aylantiradi.
  2. Ignition (Interpreter): AST dan tezda bayt-kod (Bytecode) hosil qilib, kodni darhol yurgizib yuboradi.
  3. TurboFan (Optimizing Compiler): Agar biror funksiya tez-tez chaqirilsa (Hot code), TurboFan uning qabul qilayotgan tiplarini kuzatadi va to'g'ridan-to'g'ri o'ta tezkor Mashina Kodiga (Machine Code) o'tkazadi. Agar tip to'satdan o'zgarib qolsa (masalan har doim son kelayotgan funksiyaga satr kelsa), dvigatel uni "Deoptimize" qiladi va sekinroq bayt-kodga qaytaradi. Shu sababli TypeScript yozish V8 dvigateliga ham kodni optimallashtirishda katta yordam beradi!

Execution Context va Call Stack

JavaScript kod ishga tushganda har doim Global Execution Context yaratiladi. Har safar yangi funksiya chaqirilganda, Call Stack ustiga yangi Function Execution Context qo'yiladi.

Execution Context ikki fazada ishlaydi:

  • 1. Creation Phase (Xotira ajratish fazasi): O'zgaruvchilar va funksiyalar skanerdan o'tkazilib, xotirada joy ajratiladi (Hoisting sababi!). var larga undefined yoziladi, let va const esa e'lon qilinmagan xolatda (TDZ) qoladi.
  • 2. Execution Phase (Bajarilish fazasi): Kod qatorma-qator o'qilib, qiymatlar o'zlashtiriladi va hisob-kitoblar bajariladi.

Scope Chain va Closures (Chuqur)

Closure (Yopilish) — bu ichki funksiyaning o'zi yaratilgan tashqi muhitidagi (Lexical Scope) o'zgaruvchilarni, hatto tashqi funksiya o'z ishini tugatib, Call Stack dan o'chib ketganidan keyin ham eslab qolish qobiliyatidir. 

// Astra Academy Amaliy Closure Namunasi: Memoization Kesh
function createCachedFetcher() {
  const cache = new Map(); // Bu xotira tashqi dunyodan himoyalangan (Private)

  return async function(url) {
    if (cache.has(url)) {
      console.log("⚡ Keshdan olindi:", url);
      return cache.get(url);
    }
    console.log("🌐 Serverdan yuklanmoqda:", url);
    const response = await fetch(url);
    const data = await response.json();
    cache.set(url, data);
    return data;
  };
}

const getAstraCourse = createCachedFetcher();

// Ikkinchi marta: closure ichidagi keshdan bir lahzada qaytadi!

Hoisting va TDZ (Temporal Dead Zone)

Quyidagi misol nima uchun xato beradi? 

console.log(a); // undefined chiqaradi (chunki var hoisted bo'lib, undefined olgan)

6-bob: Asinxron JavaScript va Event Loop

Event Loop: Microtasks vs Macrotasks

JavaScript — bir oqimli (Single-threaded) til. Unda bitta Call Stack bor. Qanday qilib u minglab tarmoq so'rovlarini qotib qolmasdan (Non-blocking) bajara oladi? Javob: Event Loop!

+--------------------+ +---------------------+ | CALL STACK | | WEB APIs | | (Funksiyalar ijro | -----> | (setTimeout, fetch, | | etiladigan joy) | | DOM Events...) | +--------------------+ +---------------------+ ^ | | v +---------------------------------------------------+ | EVENT LOOP | +---------------------------------------------------+ | | v v +--------------------+ +---------------------+ | MICROTASK QUEUE | | MACROTASK QUEUE | | (Promise .then/ | | (setTimeout, | | queueMicrotask) | | setInterval, I/O) | | *HAR DOIM BIRINCHI!| | *Microtask tugagach | +--------------------+ +---------------------+
⚠️ Intervyu Savoli: Natijani toping!
console.log('1');

setTimeout(() => {
  console.log('2');
}, 0);

Promise.resolve().then(() => {
  console.log('3');
});

console.log('4');

Javob: 1, 4, 3, 2. Sababi: 1 va 4 darhol Call Stack da bajariladi. Promise Microtask navbatiga tushadi. setTimeout esa Macrotask navbatiga tushadi. Event Loop har bir qadamda Microtask navbatini to'liq bo'shatib olmaguncha, Macrotask ga aslo o'tmaydi!

Promises va async/await ichki mexanizmi

async/await bu shunchaki Promise lar ustiga qurilgan qulay sintaksis (Syntactic Sugar). Dvigatel ichida u Generatorlar va yield mexanizmiga o'xshash ishlaydi: har safar await uchrashganda funksiya ijrosi to'xtatiladi va promise yechilgach yana davom ettiriladi.

Xatolarni boshqarish va Retry Pattern

Haqiqiy dunyoda internet tez-tez uzilib turadi, mobil tarmoqda paketlar yo'qoladi yoki server 503 Service Unavailable beradi. Professional frontend tizim foydalanuvchiga darhol "Xatolik yuz berdi" deb xafa qilmasdan, avtomatik ravishda oraliq tanaffuslar bilan qayta urinishi (Exponential Backoff Retry) kerak: 

// Astra Academy Production Retry Pattern
async function fetchWithRetry(url, options = {}, retries = 3, backoffMs = 1000) {
  try {
    const response = await fetch(url, options);
    if (!response.ok) {
      // 4xx mijoz xatolarida (masalan 401, 404) qayta so'rash mantiqsiz
      if (response.status >= 400 && response.status < 500) {
        throw new Error(`Client Error: ${response.status}`);
      }
      throw new Error(`Server Error: ${response.status}`);
    }
    return await response.json();
  } catch (err) {
    if (retries > 0) {
      console.warn(`Tarmoq xatosi. ${backoffMs}ms dan so'ng qayta urinilmoqda... Qoldi: ${retries}`);
      await new Promise(resolve => setTimeout(resolve, backoffMs));
      return fetchWithRetry(url, options, retries - 1, backoffMs * 2); // 1s, 2s, 4s...
    }
    throw err;
  }
}

9-bob: React.js Chuqur: Reconciliation va Fiber Arxitekturasi

Virtual DOM va Diffing algoritmi

React nima uchun tez ishlaydi? Chunki u to'g'ridan-to'g'ri og'ir brauzer DOM ini o'zgartirmaydi, balki xotirada yengil JavaScript ob'ektlari daraxtini (Virtual DOM) saqlaydi.

Holat (state) o'zgarganda yangi Virtual DOM yaratiladi va eski Virtual DOM bilan taqqoslanadi. Bu jarayon Reconciliation deyiladi. O'zgarishlarni topish uchun React O(n) murakkablikdagi Heuristic Diffing algoritmidan foydalanadi:

  • Har xil turdagi ikkita element har xil daraxt hosil qiladi (eski daraxt to'liq o'chirilib, yangisi quriladi).
  • Elementlar ro'yxatida har bir elementga noyob va o'zgarmas key berilishi shart. Aks holda React qaysi element o'zgarganini bilolmay butun ro'yxatni qayta chizadi!

React Fiber: To'xtatib bo'ladigan render

React 15 da render jarayoni sinxron (Stack Reconciler) edi. Agar sahifada 5000 ta komponent bo'lsa, React ularni yangilab bo'lmaguncha foydalanuvchi klaviaturada birorta harf ham yoza olmas edi.

React 16 da yaratilgan Fiber arxitekturasi bu ishni butunlay o'zgartirdi:

  • Endi render jarayoni kichik bo'laklarga (Fibers) bo'linadi.
  • React har bir bo'lakni bajarayotganda requestIdleCallback yordamida brauzerda boshqa muhim ish bormi-yo'qligini tekshiradi.
  • Agar foydalanuvchi tugmani bossa (User input yuqori prioritetga ega!), React joriy renderlashni to'xtatib turadi, foydalanuvchiga javob beradi va so'ngra to'xtagan joyidan davom ettiradi!

  2. Komponentga kelayotgan props o'zgarganda.

Professional Custom Hooklar yaratish

Biznes mantiqni UI komponentidan ajratishning eng toza yo'li — Custom Hook: 

// Astra Academy useDebounce Hooki
import { useState, useEffect } from 'react';

export function useDebounce<T>(value: T, delayMs: number = 400): T {
  const [debouncedValue, setDebouncedValue] = useState<T>(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delayMs);

    return () => clearTimeout(timer);
  }, [value, delayMs]);

  return debouncedValue;
}

13-bob: Web Performance & Core Web Vitals (LCP, INP, CLS)

Core Web Vitals: LCP, INP va CLS

Google saytlarni qidiruv natijalarida yuqoriga chiqarishda 3 ta o'lchovga qaraydi:

  • LCP (Largest Contentful Paint) < 2.5s: Sahifadagi eng katta blok (odatda asosiy rasm yoki h1 sarlavha) qanchalik tez ko'rindi?

  • CLS (Cumulative Layout Shift) < 0.1: Sahifa yuklanayotganda rasmlar yoki reklamalar sababli matnlar sakrab-sakrab ketmasligi kerak. Buning uchun barcha rasmlarga width va height atributlari majburiy qo'yilishi shart!

15-bob: Production, Xavfsizlik va Karyera Yo'li

Frontend xavfsizligi: XSS, CSRF va CSP

Frontend dasturchi faqat dizayn emas, foydalanuvchi xavfsizligining birinchi qalqonidir:

  • XSS (Cross-Site Scripting): Hujumchi foydalanuvchi izohlari orqali sahifaga zararli <script> kodini joylashtirishi. Hech qachon tekshirilmagan satrni dangerouslySetInnerHTML orqali ekranga chiqarmang!
  • CSRF (Cross-Site Request Forgery): Autentifikatsiyada tokenlarni localStorage da emas, balki HttpOnly, Secure va SameSite=Strict bo'lgan Cookie larda saqlang. Shunda XSS sodir bo'lsa ham xaker tokenni o'g'irlay olmaydi!
  • CSP (Content Security Policy): Brauzer qaysi domenlardan skript yoki rasm yuklay olishini qat'iy cheklovchi HTTP sarlavhasi.

Docker va GitHub Actions CI/CD

Frontend loyihani barcha kutubxonalari bilan birgalikda yengil konteynerga o'rash uchun Multi-stage Dockerfile tuziladi: 

# 1-bosqich: Dependencies & Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 2-bosqich: Production Nginx Server (Atigi 25 MB!)
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Deploy: Vercel, Cloudflare Pages va VPS

Zamonaviy deployment platformalarining afzalliklari:

  • Vercel: Next.js loyihalar uchun eng tabiiy uy. Har bir Git Pull Request uchun avtomatik Preview URL yaratadi.
  • Cloudflare Pages: Dunyo bo'ylab 300+ shaharlarda joylashgan bepul chekka (Edge) CDN tarmog'i orqali sahifalarni 10-20 ms da yuklaydi.
  • VPS (Ubuntu + Nginx + PM2): Agar ma'lumotlar O'zbekiston ichida (tas-ix) turishi talab etilsa, Nginx teskari proksi (Reverse Proxy) orqali SSL sertifikatlar bilan sozlanadi.
